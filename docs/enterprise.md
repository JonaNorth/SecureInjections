# Feed editions and organizational policy

The engine accepts community, commercial, and private feeds through the same open rule schema,
semantic index, signature verification, and atomic installer. There is no billing, license
enforcement, hidden API, or artificial technical restriction in the open-source engine.

A community feed can contain public attack patterns and examples under redistributable licenses. A
commercial curator can ship faster updates, additional provenance, tuned examples, and support. An
organization can maintain private rules and policies for its own vocabulary. Edition is manifest
metadata, not a capability switch.

Organizations should keep signing keys separate by edition and environment, pin explicit key IDs,
test candidate feeds against local benign corpora, and promote immutable versions through staged
environments.
